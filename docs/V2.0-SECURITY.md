# V2.0-SECURITY — Model Ancaman, Jaminan Integritas, & Panduan Demo

> Dokumen akademik pendamping WebCam Guard v2.0. Semua angka dalam
> dokumen ini berasal dari eksekusi nyata di lingkungan lab (lihat
> metode di tiap bagian). Klaim TANPA bukti sengaja tidak dibuat.

## 1. Tujuan & Lingkup

WebCam Guard adalah lab keamanan webcam **lokal** untuk pembelajaran
terbimbing: pemantauan kamera milik sendiri, mirroring layar dengan
persetujuan eksplisit, dan modul keamanan ofensif/defensif yang
terkunci scope. Bukan produk produksi; batas jujur ada di §6.

**Yang DIOTORISASI:** perangkat milik sendiri, host lab
(`lab-01.local`, `lab-02.local`, `192.168.56.0/24`), data sintetis.
**Yang TIDAK:** target eksternal, kredensial nyata, rekaman orang lain,
penyadapan tersembunyi (dilarang keras oleh desain).

## 2. Model Ancaman (ringkas)

| Aset | Pelaku | Ancaman | Mitigasi utama | Sisa risiko |
|---|---|---|---|---|
| Rekaman webcam | Malware lokal / pengguna lain di host | pencurian rekaman, rekaman sembunyi | indikator status eksplisit, retensi umur+kuota (`privacy.py`), izin 0600 | OS yang tidak menghormati izin file; tidak ada enkripsi at-rest |
| Rantai audit/event | Penyerang dengan akses tulis file | hapus/edit/replay baris log | hash-chain SHA-256 + seq + anchor (`audit_core`, `forensics`) | penyerang yang menguasai HOST bisa menulis ulang file+anchor bersamaan (butuh penyimpanan luar — §3) |
| Sesi mirroring | Penonton tidak diundang / MITM | brute force token, spoof role, TLS MITM | lockout per-IP 5x/60s, role dari token_map sisi server, pinning SHA-256 (wajib `--pin`) | pin dicompare manual oleh manusia (sudah dicetak server); revokasi token tidak persisten antar-restart |
| Deteksi anomali netmon | Trafik adversarial | false positive/negative | threshold configurable + evaluasi berlabel (§5) + skor & bukti per temuan | heuristik — bukan ML; interval jitter tinggi bisa lolos (recall 0.75 pada fixture) |
| Kredensial lab | Kebocoran via log/laporan | secret muncul polos | `mask()` kebijakan ketat (tanpa prefix/suffix) + verifikasi `no_secret_leak` | hanya pola yang dikenal; secret ber-format baru bisa lolos |
| Bukti forensik | Manipulasi pasca-insiden | laporan dari bukti yang dirapikan | `evidence.py` verify READ-ONLY, manifest SHA-256, kelas raw vs derived | manifest tidak ditandatangani kunci asimetrik |

## 3. Jaminan & Batasan Hash-Chain + Anchor

**Jaminan (terverifikasi oleh `tests/test_audit_fixes.py`, 27 test):**

1. **Hash-chain**: setiap baris = `sha256(prev_hash|ts|aktor|aksi|detail)`;
   mengubah/menghapus/menyisipkan baris merusak semua hash setelahnya —
   `verify()` melaporkan baris pertama yang rusak.
2. **Seq**: nomor urut eksplisit; penyisipan duplikat terdeteksi;
   baris legacy v1.3 (tanpa seq) tetap terbaca.
3. **Concurrent append aman**: `flock` per-file (POSIX) — 2 proses ×
   30 thread × 60 append total menghasilkan rantai utuh tanpa
   interleaving korup.
4. **Anchor (checkpoint)**: snapshot `{n, anchor_seq, anchor_hash,
   file_sha256}` ditulis ATOMIK (temp + rename). Truncation relatif
   anchor terdeteksi (`"TERPANGKAS: 3 < 5"`) — hal yang TIDAK bisa
   dideteksi rantai biasa.
5. **Malformed toleran**: baris bukan-JSON/non-dict dilaporkan sebagai
   baris bermasalah, tanpa exception.

**Batasan (jujur, by design):**

- **Anchor di host yang sama** = bukan anchor tepercaya terhadap
  penyerang yang menguasai host: ia bisa menulis ulang file log DAN
  file anchor bersamaan. Anchor yang kuat butuh penyimpanan luar
  (mis. write-once / mesin lain) — disebut jujur di laporan, karena
  menambah layanan jaringan di luar scope lab.
- **Truncation TANPA anchor tidak terdeteksi** oleh rantai biasa
  (menghapus baris TERAKHIR tetap valid) — blind-spot ini didokumentasi
  dan ditutup oleh anchor.
- **Tidak ada tanda tangan asimetrik**: siapa pun dengan akses tulis
  bisa membuat rantai baru yang valid "dari nol". Hash-chain
  membuktikan *konsistensi internal*, bukan *asal-usul*.
- **flock = POSIX** (Linux/macOS). Di Windows, append tetap jalan
  tetapi tanpa lock antar-proses (jarak ke risiko: interleaving multi-
  proses di Windows — didokumentasi, uji manual di laptop owner).

## 4. Kepercayaan TLS Mirroring (v2.0)

- **Minimum TLS 1.2** (server & klien, `ssl` stdlib).
- **Klien TIDAK memverifikasi CA** — trust diambil dari **pinning**:
  `--pin <fingerprint>` WAJIB. Fingerprint SHA-256 DER certificate
  dicetak server saat mulai; viewer memverifikasi pin SEBELUM HELLO
  dikirim (`getpeercert(binary_form=True)`).
- **Konsekuensi jujur**: self-signed certificate tidak dipercaya
  "karena self-signed"; ia dipercaya karena manusia membandingkan
  fingerprint. Ini trust-on-first-use yang disengaja untuk lab 2 host.
- Token 256-bit dari `secrets` (bukan HMAC deterministik dari kode
  pairing seperti v1.3) — membocorkan kode pairing tidak cukup untuk
  memalsukan token.
- Timeout baca 30s + antrian kirim bounded (4) + writer thread per
  klien: penonton lambat di-drop, tidak memblok penonton lain.

## 5. Metodologi Benchmark & Evaluasi

**Evaluasi detektor netmon** (`netmon.py --evaluasi`): 9 fixture
berlabel (5 benign + 4 anomali), 100% sintetis. Hasil run nyata build
ini: TP=3, FP=0, FN=1, TN=5 → **precision=1.0, recall=0.75,
FPR=0.0, FNR=0.25**. FN = beacon dengan jitter interval tinggi
(cv>0.25) — diakui sebagai batas heuristik, bukan disembunyikan.
Angka ini mengukur perilaku pada fixture tsb, BUKAN akurasi dunia nyata.

**Benchmark append audit/event**: `time.monotonic`, N=2000 append,
3 run + warm-up, laporan median. Angka aktual build ini tercantum di
README (§ "Performa") — jangan mengutip angka build lain.

**Batasan pengukuran**: lingkungan sandbox bersama (bukan mesin
dedicated), satu jenis OS, tanpa kontrol frekuensi CPU. Satu run
TIDAK pernah dilabeli "statistically reliable".

## 6. Panduan Demo (8 skenario, 100% sintetis)

Jalankan dari root repo. Semua skenario dapat direproduksi deterministik.

1. **Monitoring normal**: `python3 netmon.py --demo`
   → 25 paket → 15 flow → metadata DNS/SNI/HTTP terbaca.
2. **Anomali terdeteksi + bukti**: demo yang sama menampilkan 3 temuan
   dengan skor & bukti per temuan (port_c2, port_scan, beacon).
3. **Aksi tanpa otorisasi DITOLAK**: `python3 redsim.py --target 8.8.8.8`
   → `DITOLAK ... (penolakan ter-audit)`, exit code 2, entri
   `REFUSED_OUT_OF_SCOPE` di `lab_audit.jsonl`.
4. **Auth gagal + rate limiting**: `python3 fuzz_lab.py --seed 42`
   → kasus F4: 5 gagal → lockout; token BENAR pun ditolak
   ("terlalu banyak upaya gagal"), IP lain tidak terpengaruh.
5. **Integritas gagal setelah tampering**: `python3 - <<'EOF'`
   (tamper baris 0 via `log.tamper(0, "X")`) → `verify()` melaporkan
   baris 0; `verify_terhadap_anchor()` → "rantai rusak di baris 0".
   Contoh lengkap di `tests/test_audit_fixes.py`.
6. **Verifikasi utuh terhadap checkpoint**: `python3 forensics.py
   --checkpoint` → anchor dibuat; verifikasi → `utuh=True` + file SHA-256.
7. **Ekspor bukti reproducible**: `python3 evidence.py --build`
   lalu `python3 evidence.py --verify` → manifest SHA-256 per file,
   kelas raw/derived, `reproduce.txt`. Verify TIDAK menulis apa pun.
8. **Perbandingan benchmark**: lihat §5 + angka di README.

## 7. Catatan Kejujuran

- Truncation tanpa anchor = blind-spot rantai (ditutup anchor, §3).
- Penyerang yang menguasai host bisa rekayasa log+anchor bersamaan.
- Deteksi netmon = heuristik; skor ≠ kepastian; port mencurigakan
  TIDAK membuktikan aktivitas jahat (ditulis di bukti tiap temuan).
- pip-audit & fingerprint certificate nyata = NOT RUN di lingkungan
  build (alat tak tersedia) — wajib dijalankan manual di laptop owner.
- Semua kredensial di repo ini SINTETIS dan dibuang setelah asesmen.
